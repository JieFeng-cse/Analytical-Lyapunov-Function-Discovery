Ledger: `docs/CONCLUSIONS.md` C44 (reconnaissance), C46 (result).

| theorem | statement |
|---|---|
| `RotorFl.T1` | `∀ r p₁ p₂, ¬ K r p₁ p₂ → L V r p₁ p₂ + φ (V r p₁ p₂) ≤ 0` |
| `RotorFl.T2` | `∀ r p₁ p₂, K r p₁ p₂ → L V r p₁ p₂ + φ (V r p₁ p₂) ≤ Cbound` |

with `K = {H ≤ 2·10⁶} ∪ {ρ < 1 ∧ p₁² ≤ 10⁴}`, `φ(v) = c·v/(2 + log v)`, `c = 5·10⁻⁵`,
`Cbound = exp(10¹⁵)·10¹⁰⁰`, `V` the C36 machine certificate (θ = 0.02, A = 20,
S = p₁⁴ + 20, counterterms t₁..t₄), and `L` the stochastic generator written with
`deriv` (including `∂²ₚ₁`). Together: `L V ≤ Cbound·1_K − φ(V)` on `T × ℝ²`.

The build tree lives on scratch (`/anvil/scratch/x-cchen47/lean/rotor-fl`,
symlinked from `~/lean/rotor-fl`); this directory holds the sources only.

## Build on Anvil

The Lean toolchain's bundled clang needs GLIBC ≥ 2.29 (Anvil has 2.28), so C
compilation goes through a gcc wrapper, and Mathlib's cache tool needs the
system CA bundle and the `mathlib4-master` container:

```bash
export PATH="$HOME/.elan/bin:$PATH"
module load curl/7.76.1
export LEAN_CC=~/lean/leancc.sh
export CURL_CA_BUNDLE=/etc/pki/tls/certs/ca-bundle.crt
export MATHLIB_CACHE_GET_URL=https://lakecache.blob.core.windows.net/mathlib4-master
cd ~/lean/rotor-fl && lake exe cache get && lake build
```

Home quota is 25 GB; elan, the Mathlib cache and the build tree are on scratch
with symlinks (`~/.elan`, `~/.cache/mathlib`, `~/lean`). For fast iteration the
Mathlib oleans and the toolchain are mirrored to node-local `/tmp/x-cchen47-lean`
(one `lake env lean` check ≈ 3 s instead of ≈ 5 min from scratch).
